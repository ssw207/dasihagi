# 메타프롬프트 — 저장 후 화면 이동

## 목표 (사용자 요구 원문 포함)
사용자: "저장하면 모달이 꺼지거나 이전화면으로 가야되는데 이동이안됨"
→ 프리셋 편집에서 저장 버튼 클릭 후 편집 화면(모달/에디터)에 그대로 남아 목록으로 돌아가지 않음. 저장 성공 시 이전 화면(프리셋 목록)으로 이동해야 함.

## 변경 범위 (파일별)
- `popup/popup.js` — `#btn-save-preset` 클릭 핸들러: 저장 성공 후 `backToList()` 호출로 목록 뷰로 전환
- `popup/popup.js` — `#btn-save-group`은 이미 `groupBackToList()` 호출 중이므로 참고용, 프리셋만 수정
- `dist/popup/popup.js` — `npm run build`로 재생성
- 테스트 — 기존 `test:replay`/`test:qa`에 영향 없음, 수동 확인: 편집에서 저장 클릭 시 목록으로 돌아가는지, 새로 만든 프리셋이 목록에 보이는지

## 구현 상세
- 현재 `$('#btn-save-preset')` 핸들러는 저장 성공 후 `showToast('저장되었습니다.')`, `renderFields()`, 버튼 활성화만 하고 `backToList()`를 호출하지 않음
- 수정: 저장 성공(`resp.ok`) 분기에서 `showToast` 후 `backToList()` 호출. `backToList()`는 `editorView` 숨기고 `listView` 보이고 `loadPresets()` 호출하므로 새로 저장된 프리셋이 목록에 반영됨
- 신규 생성 시 `editingPreset = resp.data` 할당 후에도 `backToList()`가 `loadPresets()`를 하므로 목록 갱신됨 — `renderFields()` 호출은 불필요하므로 제거하거나 `backToList` 전에 호출해도 무해
- 취소(`#btn-cancel-editor`, `#btn-back`)는 이미 `backToList`를 호출하므로 일관성 유지
- 그룹 저장은 이미 `groupBackToList()`로 목록 이동 중이므로 변경 없음

## MUST NOT
- 저장 실패 시 이동 금지 — `resp.ok`가 false면 토스트만 보이고 에디터에 머무름 (검증 메시지 확인 가능)
- 저장 중 연타 방지 로직(`btn.disabled`) 유지
- `fields` 정규화(`normalizeFieldLabels`) 순서 유지

## 검증 방법
- `npm run check` — exit 0
- `npm run build` — exit 0
- 수동: 프리셋 편집 → 이름 변경 → 저장 → 목록으로 돌아가는지, 토스트 "저장되었습니다." 뜨는지, 목록에 변경된 이름 반영되는지
- 수동: 새 프리셋 생성 → 저장 → 목록에 새 프리셋 보이는지
- `npm run test:replay` — 181/181 유지
