# 메타-프롬프트: 프리셋별 전체 암호화 전환

작성일: 2026-08-16
근거: 사용자 요청 "그냥 통으로 암호화해서 저장 하는식으로 하는게 어때?" + 설계 확인
(암호화 범위 = 프리셋별 덩어리, pii-detect.js = 마스킹 UX용 유지)

## 1. 목표 (사용자 요구 원문)

> "그냥 통으로 암호화해서 저장 하는식으로 하는게 어때?"

선택 확정:
- **프리셋별 덩어리**: 프리셋 전체를 `sec:preset:<id>` 하나로 AES-256-GCM 암호화
- **pii-detect.js 유지**: UI 마스킹(`••••••` 표시, 민감 복사 경고) 전용으로만 사용

## 2. 배경 / 왜 바꾸는가

- 기존 필드 단위(`sec:<presetId>:<fieldId>`)는 감지가 완벽해야 보호가 완성됨.
  감지 누락 시 해당 PII가 평문 저장 → 방금 디버깅하던 "RECORD_SAVE가 `sensitive`를 복사하지 않아
  이메일이 평문으로 저장되던 버그"가 정확히 이 취약성의 증거.
- 전환 후: 모든 필드 값이 프리셋 단위로 통째 암호화 → **보호가 감지 품질과 분리**.
  감지가 불완전해도 저장소에는 평문이 하나도 없음.
- per-field 키 관리, 민감 해제 시 deleteSecret 정리, resolvePreset 복호화 경로가 모두 소멸 → 단순화.

## 3. 데이터 모델 (최종)

```
presets      (평문 인덱스)  : [{ id, name, urlPattern, updatedAt }]
                              → AUTO_APPLY 매칭 / 목록 fallback / 삭제 조회용 (복호화 불필요)
sec:preset:<id> (암호화 blob): { id, name, urlPattern, fields, autoApply, createdAt, updatedAt }
                              → fields[].sensitive = 마스킹 표시 신호 (PiiDetect 자동 + 사용자 체크박스)
groups       (평문)         : 기존 구조 유지 (스텝의 presetId 참조)
vault_key_v1 (평문 키)      : 기존 유지
```

- secure-store.js API **변경 없음**: `setSecret('preset:' + id, JSON.stringify(preset))`, `getSecret`, `deleteSecret` 재사용.

## 4. 파일별 변경

### 4.1 background.js
- accessor 추가:
  - `getPresetIndex()` / `savePresetIndex(index)` → `presets` 키
  - `getPresetById(id)` → `sec:preset:<id>` 복호화 후 JSON.parse, 실패/부재 시 null
  - `getAllPresets()` → 인덱스 순회 복호화, 실패 시 인덱스 항목 fallback (fields: [])
  - `savePreset(preset)` → setSecret + 인덱스 upsert
  - `deletePreset(id)` → deleteSecret + 인덱스 제거
- `resolvePreset`/`resolvePresets` **제거** (전체 복호화라 불필요)
- 핸들러 재작성:
  - `PRESET_CREATE`: savePreset 후 반환
  - `PRESET_UPDATE`: getPresetById → 병합 → savePreset (필드 단위 암호화 분기 제거)
  - `PRESET_DELETE`: deletePreset + 기존 그룹 스텝 정리 유지
  - `CAPTURE_SAVE_FIELD`: getPresetById → 필드 upsert (sensitive 포함) → savePreset
  - `RECORD_SAVE`: getPresetById → fields 교체 → savePreset.
    **필수 버그 수정: `sensitive: !!e.sensitive` 반드시 복사** (마스킹 신호 보존)
  - `PRESET_LIST`: getAllPresets 반환 (모든 값 복호화된 상태)
  - `APPLY_PRESET`: getPresetById → urlPattern 검증 → content로 전송
  - `AUTO_APPLY_CHECK`: **인덱스 urlPattern 매칭** → 매칭 프리셋만 getPresetById → 전송
  - `EXPORT_DATA`: getAllPresets → 기존 내보내기
  - `IMPORT_DATA`: 검증 → 각 프리셋 새 id 부여 → setSecret('preset:'+id, JSON) + 인덱스 갱신
- **마이그레이션** `migrateLegacyStorage()` (시작 시 1회, restoreRunState 이전):
  - 판정: `presets[0]`에 `fields` 존재 = 레거시
  - 각 프리셋: 필드별 `sec:<presetId>:<fieldId>` 복호화로 값 복원 → `sec:preset:<id>` 저장 →
    인덱스 작성 → 필드별 sec 키 deleteSecret 정리
  - 레거시가 아니면 no-op

### 4.2 content.js / popup.js / pii-detect.js
- **변경 없음**. content의 PiiDetect 감지·녹화 로직, popup의 민감 체크박스/마스킹 UX 모두 유지
  (sensitive는 이제 "암호화 대상"이 아닌 "마스킹 표시 대상" 신호).

### 4.3 테스트
- `test/encryption-verify.mjs`: 필드 단위 의미 → 프리셋 blob 의미로 재작성 (의미 보존):
  - S1: presets 배열에 필드 값 평문 미노출 (인덱스만)
  - S2: `sec:preset:<id>` 암호문 존재, 평문 값 문자열 미노출
  - S3: PRESET_LIST 복호화 값 반환
  - S4: APPLY_PRESET 복호화 값 전달
  - S5: PRESET_UPDATE 재암호화 (값 변경 반영)
  - S6: IMPORT_DATA 재암호화 (새 id, 새 암호문)
  - S7: PRESET_DELETE 시 blob + 인덱스 정리
  - S8: EXPORT_DATA 복호화 평문 내보내기
  - S9: 키 불일치 시 getSecret null (블랍 복호화 실패 대응)
- `test/record-replay-verify.mjs`: RECORD_SAVE 검증을 blob 기준으로 갱신 +
  **sensitive 보존(마스킹 신호) 검증 추가** (이메일 sensitive=true 유지, 이름 필드도 감지 결과 반영)
- `test/pii-detect-verify.mjs`: 변경 없음 (30/30 유지)

## 5. MUST NOT (금지)

- content.js 녹화/재생/캡처 로직 변경 금지
- popup 마스킹 UX, 민감 체크박스 제거·동작 변경 금지
- pii-detect.js 로직 변경 금지
- 필드 단위 sec 키(`sec:<presetId>:<fieldId>`) 신규 생성 금지
- 기존 테스트 삭제로 통과 금지 (의미 보존 재작성만 허용)
- `as any`, `@ts-ignore`, 빈 catch로 통과 금지

## 6. 검증 방법

1. `npm run check` 통과 (node --check + manifest/build 검증)
2. `npm run build` 통과 (dist 생성)
3. `npm run test:encrypt` 재작성분 전부 통과
4. `npm run test:pii` 30/30 유지
5. `npm run test:replay` 통과 (sensitive 보존 검증 포함)
6. 레거시 마이그레이션 경로 케이스 통과
7. REQUIREMENTS.md 체크리스트 갱신 후 커밋 대기 (커밋은 사용자 명시 시)
