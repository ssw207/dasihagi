# 메타프롬프트 — 기획서 역생성

## 목표

사용자 요구 원문: **「현재 프로젝트 기반으로 기획서를 역으로 생성」** / 이어서 **「계속」**

이미 구현된 **다시하기(dasihagi)** Chrome 확장을 기준으로, 처음부터 기획했을 때 나왔어야 할 **제품 기획서**를 역으로 작성한다. 기술 요구사항 정의서(`REQUIREMENTS.md`)를 복사하지 않는다. 누가·왜·무엇을·하지 않는지를 제품 문서로 정리한다.

근거: `README.md`, `REQUIREMENTS.md`, `유즈케이스-실사용자.md`, `.sisyphus/notepads/form-preset-extension/decisions.md`(D1~D33), `manifest.json`, `popup/popup.html`, `background.js`/`content.js` 실제 동작. 구현되지 않은 기능을 있는 것처럼 쓰지 않는다.

## 변경 범위 (파일별)

| 파일 | 할 일 |
|------|--------|
| `기획서.md` (신규, 저장소 루트) | 역생성 기획서 본문 |
| `REQUIREMENTS.md` | 관련 문서·변경 이력에 기획서 링크 |
| `.sisyphus/notepads/form-preset-extension/decisions.md` | D34: 기획서 역생성 |
| `README.md` | 개발자 절에 기획서 링크 한 줄 |

코드·스키마·UI 문자열·테스트는 건드리지 않는다.

## 구현 상세

기획서 목차(필수):

1. 문서 정보 (역생성 사실, 기준 버전 0.1.0, 관련 문서)
2. 배경과 문제
3. 제품 정의 (한 줄, 포지셔닝, 제품명이 바뀐 이유)
4. 목표 / 비목표
5. 사용자·페르소나 (유즈케이스 P0 중심)
6. 핵심 가치와 성공 조건
7. 기능 범위 (In / Out) — 구현된 R1~R18을 사용자 언어로
8. 정보 구조와 화면 (popup 탭, 카드, 편집, 페이지 칩)
9. 핵심 사용자 흐름 (녹화·재생·여정·그룹·캡처)
10. 데이터·보안·프라이버시 (암호화 범위와 한계를 과장하지 않음)
11. 제약·한계·리스크
12. 비기능·배포
13. 로드맵 (완료 / 보류 D10·D14 / UI P1·P2는 후보로만)
14. 용어
15. 부록: 요구사항 ID 매핑 표

문체: 한국어, 단정. “향후 예정”처럼 구현을 약속하지 않음. 사이트 하드코딩 없음.

## MUST NOT

- 매크로·봇·오픈런·캡차 우회를 제품 목표로 쓰지 않음
- 미구현을 현재 기능처럼 쓰지 않음
- Playwright를 제품 런타임으로 쓰지 않음
- `REQUIREMENTS.md`를 붙여넣기하지 않음
- 소스 코드 변경 금지
- 새 결정 번호를 질문 회고용으로 쌓지 않음 — 산출물 확정만 D34

## 검증

- 기획서의 In/Out이 README 「이 제품으로 하지 않는 일」과 모순되지 않음
- 여정 vs 그룹 구분이 README 표와 같음
- 암호화: 프리셋 blob AES-256-GCM, PII는 마스킹 신호, 내보내기는 평문 JSON — 세 가지가 섞이지 않음
- 코드 미변경: `git status`에 문서만
