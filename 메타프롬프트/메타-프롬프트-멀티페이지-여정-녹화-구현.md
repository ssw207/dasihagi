# 메타 프롬프트: 멀티페이지 사용자 여정 녹화·재생 구현

## 역할

너는 Chrome 확장 프로그램(폼 프리셋, MV3)의 녹화/재생을 확장하는 시니어 프론트엔드 엔지니어다. 아래를 **코드 탐색 후** 최소 변경으로 구현하고 검증까지 완료한다.

## 배경 / 사용자 요구 원문

> 지금 녹화기능은 한 페이지만 가능한거 같은데. 아예 사용자 움직임을 전부 녹화하고 재생하고 싶어.
> 가령 네이버 메인에 들어가서 수저세트를 검색하고 > 네이버 가격비교 더보기를 클릭 > 가격비교
> 검색창에 인기 수저세트 입력후 확인 > 그리고 한 제품을 선택
> 이걸 한 프로셋으로 녹화하고싶은데 …

D19 판정: **현재 불가 / MV3 조건부 가능**. 사용자가 **구현 진행**을 지시함.

## 목표 동작

1. 녹화 시작 후 사용자는 **평소처럼** 입력·검색·클릭·페이지 이동을 한다.
2. 페이지가 바뀌어도 **같은 녹화 세션**이 이어지고, 칩(`녹화 중 · N개` + 종료)이 다시 보인다.
3. 종료 시 입력·클릭·Enter·URL 이동이 **하나의 프리셋 `fields[]`**에 순서대로 저장된다.
4. 재생 시 **같은 탭**에서 시작 URL로 맞춘 뒤 순서대로 값 채움/클릭/Enter/이동을 재현한다.
5. 기존 한 페이지 폼 녹화·재생·캡처·그룹·암호화는 그대로 동작한다.

## 핵심 설계

- 버퍼의 단일 원본은 **background + `chrome.storage.session`** (`recordSessions[tabId]`).
- content는 확정된 행동만 `RECORD_APPEND`로 보낸다. 페이지 이동 시 content 메모리는 버려도 된다.
- `tabs.onUpdated` complete → 녹화 중 탭이면 `RECORD_START { resume, eventCount }`로 칩/리스너 복원. URL 변경이면 `navigate` 이벤트 추가(직전 navigate와 URL 같으면 생략).
- 새 `type`: `click` | `keydown` | `navigate`. 기존 `text/select/checkbox/radio/textarea` 유지.
- `isJourneyPreset`: 위 세 type이 하나라도 있으면 여정. 재생은 background 상태 머신(같은 탭). 아니면 기존 APPLY_PRESET → content.
- 여정은 **자동 적용하지 않는다** (페이지 진입마다 클릭이 나가면 위험).
- 프리셋에 선택 필드 `startUrl`(녹화 시작 탭 URL). 하위 호환.
- 클릭 재생: 셀렉터 실패 시 보이는 글자(`value`)로 `a, button, [role=button], [role=link], input[type=submit|button]` 폴백.
- 네이버 하드코딩 금지. 동적 목록은 깨질 수 있음을 README에 명시.

| 파일 | 변경 |

| `REQUIREMENTS.md` / `decisions.md` / `README.md` | R11, D20, 사용법 |

`secure-store.js` 변경 금지. 캡처 모드 동작 변경 금지.

## 금지 사항 (MUST NOT)

- 네이버 전용 URL/셀렉터 하드코딩.
- 기존 폼 전용 녹화 테스트(필드 4개·delay·암호화) 깨기.
- 여정 프리셋 자동 적용.
- 녹화 중 클릭 `preventDefault`/하이라이트로 페이지 방해.
- 그룹 실행을 새 탭 여정으로 바꾸기 (그룹은 그대로).
- `as any` / `@ts-ignore` / 빈 catch.
- 다른 세션 QA 미커밋을 목적 없이 되돌리기.
