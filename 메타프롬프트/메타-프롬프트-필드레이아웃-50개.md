# 메타프롬프트 — 필드 저장 레이아웃 50개 대응

## 목표 (사용자 요구 원문 포함)
사용자: "필드 저장 레아웃 개선. 필드가 50개라면 지금 UI로는 가독성떨어짐"
→ 편집 화면(`#preset-editor-view`)의 필드 리스트가 50개일 때 현재 카드형(패딩 8px, 여러 줄의 체크박스/버튼)이 세로로 너무 길어 스크롤이 많고 한눈에 구분이 안 됨. 컴팩트하게 개선.

## 변경 범위 (파일별)
- `popup/popup.html` — 편집 필드 헤더(`fields-head`)에 검색 입력(`#field-search`)과 개수/필터 표시 추가
- `popup/popup.js` — `renderFields()`를 컴팩트 단일 행 레이아웃으로 변경, 검색 필터링 로직 추가, `field-search` 이벤트 바인딩
- `popup/popup.css` — `.field-item`을 컴팩트(패딩 4×6, 간격 3px, 폰트 11px), 한 줄에 라벨/타입/값/액션을 배치, 50개 스크롤 시 헤더 고정(sticky), 검색 입력 스타일
- `dist/` — `npm run build`로 재생성
- 테스트 — `check`/`replay`/`qa` 영향 없음, 수동: 50개 필드 프리셋 편집 시 가독성 및 검색 동작

## 구현 상세
### 1) 컴팩트 필드 아이템
- 현재 `.field-item`은 `field-item-top`(라벨+타입), `field-selector`, `field-value-row`(값/민감/손댈/금지/다시찍기/삭제)로 2~3줄 차지. 50개면 150줄.
- 변경: 한 줄에 `라벨(120px) | 타입배지 | 값(유동) | 액션(복사/다시찍기/삭제)`로 압축. `field-selector`는 토글 버튼으로 숨김 유지, `field-value-row`는 `flex` 한 줄, 체크박스 3개(민감/손댈/금지)는 `...` 더보기로 접기 또는 작은 아이콘으로 축소. 가장 중요한 `라벨-값-타입`만 한눈에 보이게.
- CSS: `.field-item { display:flex; align-items:center; gap:6px; padding:4px 6px; margin-bottom:3px; font-size:11px }`, `.field-label-input { flex:1 1 90px; font-size:11px; padding:3px 5px }`, `.field-type { font-size:9px; padding:1px 4px }`, `.field-value-row { flex:1 1 auto; gap:4px }`, 입력 `padding 3px 6px; font-size:11px`

### 2) 검색/필터
- HTML: `fields-head` 아래에 `<input id="field-search" placeholder="필드 검색 (라벨/값/타입)" style="width:100%; margin:6px 0; ...">` 추가 (JS에서 동적 생성해도 되고 HTML에 직접)
- JS: `renderFields()` 시작 시 `const q = ($('#field-search')?.value || '').toLowerCase().trim()`로 필터. `fields.filter(f => !q || f.label.toLowerCase().includes(q) || String(f.value).toLowerCase().includes(q) || f.type.includes(q))`로 필터링. 필터된 목록만 렌더, 상단 `field-count`는 `필터된수/전체수`로 표시. 검색 입력 `input` 이벤트에서 `renderFields()` 재호출 (디바운스 150ms)
- 빈 결과 시 `"검색 결과 없음"` 표시

### 3) 헤더 고정 및 가상화는 제외
- 50개는 DOM 50개로도 충분히 빠름(가상화 불필요). 대신 `.fields-list`에 `max-height: 320px; overflow-y:auto`와 `fields-head`를 `position:sticky; top:0; background: #f9fafb;`로 고정해 스크롤 시에도 검색/개수가 보이게.

## MUST NOT
- 필드 데이터 구조(`fields[]`의 `label/value/type/selector/sensitive/handEdit/replayBlocked`) 변경 금지
- 저장 로직(`normalizeFieldLabels`, `CAPTURE_SAVE_FIELD`, `PRESET_UPDATE`) 변경 금지
- 기존 체크박스 기능(민감/손댈/금지) 제거 금지 — 접더라도 토글로 유지
- `popup.html`의 다른 섹션(프리셋 목록/그룹) 레이아웃에 영향 금지

## 검증 방법
- `npm run check` — exit 0
- `npm run build` — exit 0
- 수동: 편집에서 필드 50개 프리셋 열기 → 한 화면에 8~10개가 보이고 스크롤 시 헤더/검색 고정, 검색어 "이름" 입력 시 해당 필드만 필터링, 값 복사/다시찍기/삭제 정상 동작
- `npm run test:replay` — 181/181 유지
