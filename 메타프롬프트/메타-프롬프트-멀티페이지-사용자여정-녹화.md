# 메타 프롬프트: 멀티페이지 사용자 여정 녹화 — 가능 여부 확인

## 역할

너는 Chrome 확장 프로그램(폼 프리셋, MV3)의 녹화/재생 설계를 검토하는 시니어 프론트엔드 엔지니어다. 아래 요구사항을 **먼저 실제 코드베이스를 탐색한 뒤**, **구현하지 말고** 가능 여부를 판정하고 근거·갭·구현 시 필요 변경을 문서화한다. 이번 라운드의 산출물은 판정과 문서 갱신이다.

## 배경 / 사용자 요구 원문

> 지금 녹화기능은 한 페이지만 가능한거 같은데. 아예 사용자 움직임을 전부 녹화하고 재생하고 싶어. (다른 세션에서 작업하다가 말은 흔적이 있을수도있다)
> 가령 네이버 메인에 들어가서 수저세트를 검색하고 > 네이버 가격비교 더보기를 클릭 > 가격비교
> 검색창에 인기 수저세트 입력후 확인 > 그리고 한 제품을 선택
> 이걸 한 프로셋으로 녹화하고싶은데 가능한지 확인하는 프롬프트를 만들어줘 그리고 그 프롬프트로 실행해

사용자는 **한 페이지 폼 채움**이 아니라 **여러 페이지에 걸친 사용자 행동 전체**(검색, 클릭, 페이지 이동, 다시 검색, 상품 선택)를 **하나의 프리셋**으로 녹화·재생하고 싶다.

## 목표 (이번 라운드)

1. 현재 녹화/재생이 **한 페이지·폼 필드만**인지 코드로 확정한다.
2. 사용자 시나리오(네이버 메인 → 검색 → 가격비교 더보기 → 재검색 → 상품 선택)를 현재 기능으로 **그대로 한 프리셋에 녹화·재생할 수 있는지** 판정한다.
3. Chrome Extension MV3에서 **구현 가능한지**(지금 불가여도 설계로 가능한지)와 **불가능한 한계**를 분리한다.
4. 다른 세션 흔적(미커밋, `.sisyphus/`, 기존 메타프롬프트)에 동일 주제가 있는지 확인한다.
5. 판정 결과를 `REQUIREMENTS.md`(보류 항목), `.sisyphus/notepads/form-preset-extension/decisions.md`(D19), `README.md`(녹화 한계 한 줄)에 반영한다.

## 대상 시나리오 (수용 기준의 원형)

한 번의 녹화 세션에서 다음이 하나의 프리셋에 기록되고, 재생 시 같은 순서로 재현되어야 “가능”이다.

| 단계 | 사용자 행동 | 필요한 이벤트 종류 |
|------|-------------|-------------------|
| 1 | 네이버 메인 진입 | 시작 URL / 네비게이션 |
| 2 | 검색창에 `수저세트` 입력 후 검색 | text 입력 + Enter 또는 검색 버튼 **클릭** |
| 3 | 결과에서 `가격비교 더보기` 클릭 | **클릭** + **페이지/뷰 전환** |
| 4 | 가격비교 검색창에 `인기 수저세트` 입력 후 확인 | text 입력 + 클릭/Enter |
| 5 | 목록에서 한 제품 선택 | **클릭** + 상세/이동 |

그룹(R4: 페이지마다 별도 프리셋 + 새 탭 열기)으로 우회하는 것은 **“한 프리셋 녹화”가 아니다.** 우회 가능 여부는 별도 항목으로만 적는다.

## 구현 상세 — 탐색 체크리스트 (구현 전 필수)

코드를 읽고 아래를 **사실로 채운다.** 추측 금지.

### A. 녹화 범위
- [ ] `content.js` 녹화 리스너가 잡는 이벤트 (`input`/`change`만인지, `click`/`keydown`/`submit` 포함인지)
- [ ] `isFormField` / `recordEvent`가 폼 필드 외 요소(링크, 버튼, 카드)를 기록하는지
- [ ] Enter 키, 검색 버튼 클릭이 이벤트에 남는지
- [ ] `delay` 상한(`RECORD_MAX_DELAY`)과 페이지 전환 대기와의 관계

### B. 페이지 수명 / 버퍼
- [ ] `record` 객체가 content script 메모리에만 있는지
- [ ] 전체 페이지 이동(네이버 메인 → 검색 결과) 시 content script가 죽고 버퍼가 사라지는지
- [ ] `background.js`의 `recordTabs`가 탭 이동 후에도 녹화를 재개하는지 (`tabs.onUpdated`에서 RECORD_START 재전파 여부)
- [ ] `tabs.onRemoved`에서 `recordTabs.delete`만 하는지
- [ ] SPA(`pushState`/`replaceState`)는 `AUTO_APPLY_CHECK`만 하는지, 녹화 재개는 없는지

### C. 재생
- [ ] `replaySequential` / `applyField`가 값 채움만 하는지, 클릭·Enter·URL 이동을 하는지
- [ ] `APPLY_PRESET`이 단일 `urlPattern` 불일치 시 즉시 실패하는지
- [ ] 그룹 실행이 새 탭 + 폼 채움인지, 같은 탭 여정 재생인지

### D. 데이터 모델
- [ ] 필드 스키마(`selector/value/type/delay`)로 클릭·네비게이션을 표현할 수 있는지
- [ ] `type` enum에 click/navigate/keydown이 있는지
- [ ] 한 프리셋의 `urlPattern` 하나가 네이버 메인·검색·쇼핑을 모두 커버하는지

### E. 다른 세션 흔적
- [ ] git status 미커밋(`background.js`, `content.js`, `popup.js`, `secure-store.js`)에 여정 녹화 초안이 있는지
- [ ] `.sisyphus/notepads`, `.sisyphus/plans`, 기존 `메타-프롬프트-*.md`에 동일 요구가 있는지

### F. 판정 형식 (반드시 이 세 층으로)

1. **현재 제품으로 가능한가?** (코드 그대로, 네이버 시나리오 한 프리셋)
2. **확장으로 구현 가능한가?** (MV3, 네이티브 JS, 기존 저장소/암호화 제약 안)
3. **사이트 특성으로 깨지는가?** (네이버 동적 셀렉터, 광고, 로그인, A/B, 검색 결과 순위 변동)

각 층에 **가능 / 조건부 가능 / 불가**와 근거 파일·함수를 적는다.

구현이 가능하다면 **최소 설계**만 적는다 (이번 라운드에서 코딩하지 않음).

- 버퍼를 `chrome.storage.session` 또는 background로 이전
- 탭 complete 시 녹화 재개
- 이벤트 타입 확장: `click`, `keydown`(Enter), `navigate`
- 재생은 background 상태 머신(그룹 runState와 유사, 같은 탭 유지)
- 기존 `fields[]` 하위 호환 전략 (`type` 추가 vs 별도 `actions[]`)

## 금지 사항 (MUST NOT)

- 이번 라운드에서 여정 녹화/클릭 재생을 **구현하지 않는다.** 판정만 한다.
- 기존 프리셋 스키마·그룹 실행·암호화·캡처 모드를 바꾸지 않는다.
- “그룹으로 페이지마다 프리셋을 만들면 된다”를 **한 프리셋 여정 녹화와 동일하다고 결론 내리지 않는다.**
- 네이버 전용 하드코딩 셀렉터/URL을 코드나 요구사항에 넣지 않는다.
- 타입 억제(`as any`, `@ts-ignore`), 빈 catch로 통과 금지.
- 다른 세션 미커밋을 이 주제와 무관하게 되돌리거나 덮어쓰지 않는다.

## 실행 결과 (2026-08-16)

이번 라운드는 구현하지 않았다. 아래는 코드 탐색 판정이다.

### F. 세 층 판정

| 층 | 판정 | 한 줄 |
|----|------|-------|
| 1. 현재 제품으로 네이버 5단계를 한 프리셋에 녹화·재생 | **불가** | 폼 값만 기록하고, 페이지가 바뀌면 버퍼가 사라지고, 재생은 클릭/이동을 하지 않는다. |
| 2. MV3 확장으로 구현 | **조건부 가능** | background가 탭을 넘나들며 버퍼·재생 상태 머신을 가지면 된다. 기존 `fields[]`만으로는 부족하다. |
| 3. 네이버 같은 동적 사이트에서 안정 재생 | **조건부 가능(깨지기 쉬움)** | 셀렉터가 자주 바뀌고 검색 결과 순위가 변한다. “같은 상품을 항상 연다”는 보장할 수 없다. |

### 네이버 5단계 × 현재 코드

| 단계 | 녹화 | 재생 | 이유 |
|------|------|------|------|
| 1. 네이버 메인 진입 | 안 함 | 안 함 | URL/네비게이션 이벤트 없음. `urlPattern`은 매칭용 한 줄뿐. |
| 2. `수저세트` 검색 | 검색창 값만 (페이지가 안 바뀌면) | 값만 채움, 검색 실행 안 함 | `input`만 기록. Enter/검색 버튼 클릭 없음. 검색으로 페이지가 바뀌면 content script가 죽어 버퍼 유실. |
| 3. 가격비교 더보기 클릭 | 안 함 | 안 함 | 링크/버튼은 `isFormField`가 아니라 `onRecordInput`/`onRecordChange`에서 drop. |
| 4. `인기 수저세트` 재검색 | 새 페이지면 녹화 자체 종료 | 해당 페이지에 없으면 실패 | `recordTabs`는 Set만 유지하고 `tabs.onUpdated`에서 RECORD_START를 다시 보내지 않음. |
| 5. 제품 선택 | 안 함 | 안 함 | 클릭 미기록. 결과 카드는 동적 목록이라 셀렉터도 불안정. |

### A~E 근거 (파일·함수)

**A. 녹화 범위 — 폼 필드만**
- `content.js` `startRecordingMode`: `input`, `change`만 등록. `click`/`keydown`/`submit` 없음.
- `onRecordInput` / `onRecordChange`: `isFormField`가 아니면 return. `isFormField`는 `input`(hidden 제외)·`select`·`textarea`만.
- `detectFieldType` enum: `select` / `textarea` / `checkbox` / `radio` / `text`. click·navigate·keydown 없음.
- Enter·검색 버튼·상품 카드는 기록되지 않는다.
- `RECORD_MAX_DELAY = 5000`: 페이지 로드 대기가 아니라 직전 필드 입력 간격 상한.

**B. 페이지 수명 — 한 문서 메모리**
- `record`는 content script IIFE 변수. 전체 탐색 시 문서와 함께 소멸. `beforeunload`에 버퍼 플러시 없음.
- `RECORD_START`만 `recordTabs.add` + 그 순간 탭에 메시지. `tabs.onUpdated`(complete)는 `applyAutoPreset`과 그룹 `handleStepTabLoaded`만. 녹화 재개 없음.
- `tabs.onRemoved`: `recordTabs.delete`만. 이동이 아니라 탭 닫기.
- SPA URL 변경(`pushState`/`replaceState`/`popstate`/`hashchange`)은 `AUTO_APPLY_CHECK`만. 녹화 세션과 무관.

**C. 재생 — 값 채움만**
- `replaySequential`: delay 대기 → `querySelector` → `applyField`. `el.click()`, `KeyboardEvent`, `location`/`tabs.update` 없음.
- `applyField`: checkbox/radio/select/text value setter + input/change dispatch.
- `APPLY_PRESET`: `matchUrlPattern(preset.urlPattern, tab.url)` 실패 시 즉시 오류. 메인에서 녹화한 패턴으로 검색/쇼핑 URL이 안 맞을 수 있음.
- 그룹 `startCurrentStep`: `chrome.tabs.create({ url: patternToUrl(urlPattern) })` — **새 탭**에 각 프리셋 URL을 열고 폼을 채움. 같은 탭 여정 재생이 아님.

**D. 데이터 모델**
- 필드: `id, label, selector, value, type, sensitive, delay`. 클릭 좌표/키/이동 URL 없음.
- 프리셋당 `urlPattern` 하나. `naver.com`이면 호스트는 맞을 수 있으나 경로·동작은 표현 못 함.

**E. 다른 세션 흔적**
- 미커밋(`background.js`/`content.js`/`popup.js`/`secure-store.js`)은 QA·암호화·URL 매칭 수정. 여정 녹화 초안 없음.
- `.sisyphus/notepads`·기존 메타프롬프트에 “멀티페이지 사용자 움직임 한 프리셋” 요구 없음. R4 그룹은 별 기능.

### 그룹(R4)은 우회가 아니다

그룹은 **페이지마다 미리 만든 프리셋**을 **새 탭으로 열어 폼만 채운다.**  
네이버에서 검색어를 치고 더보기를 누르고 상품을 고르는 흐름을 한 번에 녹화하는 기능이 아니다.

### 구현한다면 (코딩하지 않음) 최소 설계

1. 녹화 버퍼를 content가 아니라 `chrome.storage.session` 또는 background에 둔다.
2. `recordTabs`에 presetId를 두고, `tabs.onUpdated` complete 때 같은 탭에 `RECORD_START`(이어쓰기) + 칩 복원.
3. 이벤트 타입 추가: `click`, `keydown`(Enter), `navigate`(URL). 기존 `fields[]`의 `type` 확장 또는 `actions[]` 분리(캡처 프리셋 하위 호환).
4. 재생은 그룹 `runState`와 비슷한 **같은 탭** 상태 머신: 액션 → 필요 시 탐색 대기 → 다음 액션.
5. 네이버 상품 선택처럼 목록이 바뀌는 클릭은 셀렉터만으로 실패하기 쉽다. “가능”이 “항상 같은 상품”을 뜻하지 않는다.

문서 반영: `REQUIREMENTS.md` §8, `decisions.md` D19, `README.md` 5단계 한계 한 줄.
