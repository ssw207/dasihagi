# 메타프롬프트 — 채움 초안 스토리 2~6 (CAP-3~7)

## 목표

사용자 요구 원문: **「전체 완료될때까지 계속 진행」** + **「설계에 따라 구현」** + **「계속진행」**

SPEC-fill-as-draft (채움 초안 — 재생 후 손댈 칸만 남기기) 스토리 2~6을 구현한다. 스토리 1(손댈 칸/나중에 입력, CAP-1·2, R19, D43)은 이미 완료·검증됨(161 PASS 중 손댈 칸 케이스 포함). 이 라운드에서 CAP-4 상신·결제·전송 재생 금지, CAP-6 파일 첨부 멈춤, CAP-5 프리셋별 속도, CAP-3 깨진 칸만 다시 찍기, CAP-7 스크럽 내보내기를 같은 SPEC 제약 아래 완성한다. 녹화 엔진 교체 없음. 여정(같은 탭)과 그룹(스텝마다 새 탭)은 합치지 않는다.

## 구현 상세

### 스토리 2 — 상신·결제·전송 클릭 재생 금지 (CAP-4, R20)

- 기본 단어(보이는 글자 정확히 일치 또는 끝남, 대소문자 무시): `상신` `결재` `결제` `결제하기` `구매하기` `전송` `송금` `이체` `Pay` `Purchase` — `marking-rules.md`에서만 온다. `제출` `확인` `저장` `다음` `검색`은 기본 금지 아님 (검색·임시저장 오차단 방지).
- 판정: 저장 시 `resolveReplayBlocked({type,value,replayBlocked})` — `type===click`만, `replayBlocked===boolean`이면 그 값, 아니면 `matchesDangerText(value)`(정확 일치/endsWith, 영문 lower 비교). 읽기 시 `getPresetById`에서 동일. 녹화 머지는 `appendSessionEvent`에서 `replayBlocked`를 다시 계산하지 않고 `last.handEdit`처럼 preserve? 클릭은 머지 대상 아님(매번 새 이벤트). 캡처도 `replayBlocked` 계산.
- 재생: `content.js applyField` 클릭에서 `isReplayBlockedClick(field, el)` — 필드 플래그가 boolean이면 그 값, 아니면 `matchesDangerText(field.value)` 또는 `visibleText(el)`로 폴백. blocked면 `fp-blocked-click`을 더하고 `{ok:true, blocked:true}`로 반환. `replaySequential`은 `blocked`를 failures에 넣지 않고 `applied`에 넣어 토스트에서 `직접 누르기 N개`로 구분, 이후 필드는 중단(`break`). `replayJourney`도 APPLY_ACTION blocked면 `applied.push` 후 `break`. 그룹 `handleStepTabLoaded` auto 제출이 blocked면 `runState=waiting`으로 사람 대기 (클릭하지 않음).
- 편집: `popup renderFields` 클릭 타입이면 `data-replay-blocked` 체크박스. 토글로 `field.replayBlocked` 갱신. 리스트 카드 클릭 필드는 `클릭 · 값` 그대로, 복사 비활성은 handEdit과 별개.
- 저장 위치: `handEdit`와 마찬가지로 blob 안 `replayBlocked:boolean`(클릭만). 평문 인덱스엔 없음. 레거시: 키 없음이면 `matchesDangerText`로 읽기 시 기본값, 저장 전까지 blob 일괄 재기록 없음.

### 스토리 3 — 파일 첨부 칸에서 멈춤 (CAP-6, R21)

- 판정: `content.js applyField`에서 `el instanceof HTMLInputElement && el.type==='file'`이면 `fp-file-stop`을 더하고 `{ok:true, fileStop:true}` 반환. 값을 채우려 하지 않는다 (확장이 file value를 넣을 수 없음). failures에 넣지 않음.
- 재생: `replaySequential`/`applyPreset` 모두 fileStop은 applied로, 이후 필드는 계속 진행 가능 (현재 구현은 중단하지 않고 계속 — 토스트에서 `직접 첨부 N개`로 알림). 여정도 동일. 그룹도 첨부 스톱은 `waiting`으로 바꾸지 않고 그냥 진행.
- 안내: `formatReplayToast`에서 `fileStop.length` 집계해 `직접 첨부 N개` 문구. 스타일 `.fp-file-stop{outline:2px dashed #f97316}`.
- MUST NOT: `input[type=file]`에 `setNativeValue` 시도 금지.

### 스토리 4 — 프리셋별 재생 속도 (CAP-5, R22)

- 데이터: `preset.replayPace: 'fast'|'normal'|'slow'|''|'undefined'` (빈 값·키 없음이면 전역 따름). 편집 `#ed-pace-row` 4버튼(전역 따름/fast/normal/slow). 저장 시 `dataset.edPace===''`이면 `''`, 아니면 해당 값. `PRESET_CREATE`도 동일? 생성 시엔 없음 → 전역 따름.
- 결정: `background.js resolvePresetPace(preset, globalPace)` — preset에 fast/slow/normal이면 그 값, 아니면 globalPace를 정규화. `content.js paceDelayMs/paceWaitElementMs`는 preset pace를 인자로 받는다. `replayJourney`와 `sendApplyToFrames APPLY_PRESET` 모두 preset pace를 계산해 content에 전달.
- 전역 `ui:replayPace`는 유지(`SETTINGS_GET/SET`). 프리셋 값이 있으면 덮음. 사이트 도메인 하드코딩 없음. 기획서 7.2 P1 후보를 R22로 P0 반영.
- 검증: `test:replay`에서 preset fast가 전역 slow를 덮어 delay가 짧아짐을 시간 측정(빠름이면 이동 후 대기 0)으로 단언.

### 스토리 5 — 깨진 칸만 다시 찍기 (CAP-3, R23)

- 메커니즘: 기존 캡처 모드를 재사용. `popup renderFields` 각 필드에 `다시 찍기` 버튼 → `CAPTURE_START {presetId, replaceFieldId: f.id}` → `content startCaptureMode`가 `replaceFieldId`를 보관 → `saveField`가 `CAPTURE_SAVE_FIELD {field, replaceFieldId}`로 background에 전달. background는 `replaceId`가 있으면 `preset.fields.findIndex(f.id===replaceId)`로 찾아 원래 `id`를 유지한 채 `value`·`selector`만 갱신(`value!=='' ? value : prev.value`, `selector || prev.selector`). 인덱스 작성부는 건드리지 않음.
- 제약: 전체 재녹화 UI를 만들지 않는다. 사용자는 페이지에서 칸을 가리키는 동작(캡처와 동일)으로 그 필드만 지정.
- 여정 중간 실패 후: `replaySequential` failures에 `fieldId`를 포함하므로, 사용자가 그 `fieldId`를 다시 찍으면 같은 프리셋을 재녹화 없이 재생 가능. `test:replay`에서 before 누락 → repick → after 채움·실패 0을 검증.
- MUST NOT: 새 녹화 엔진, 시각 매칭, 별도 리픽 API.

### 스토리 6 — 값 없는 스크럽 내보내기 (CAP-7, R24)

- 내보내기: `background scrubPresetForExport(preset)` — `JSON.parse(JSON.stringify(preset))` 뒤 `fields.map(f=>({...f, value:''}))`. `handEdit`/`replayBlocked`/`replayPace`·`sensitive` 등 표시 플래그는 유지. 그룹은 그대로. `EXPORT_DATA {scrub:true}`면 `presets: presets.map(scrubPresetForExport), groups, scrub:true`. 아니면 기존 실값 그대로.
- 가져오기: 기존 `IMPORT_DATA` 경로를 바꾸지 않는다. 스크럽 파일을 가져와도 동일하게 `validateImportData`→새 ID→재암호화. 스크럽이어도 `value===''`이므로 그대로 저장. `R5-4` 상한 검증은 그대로.
- UI: `popup downloadExport(scrub)` — `scrub? scrub:true : false`, 파일명 `presets-scrub-YYYY-MM-DD.json` vs `presets-YYYY-MM-DD.json`, 토스트 문구 `값 없이 내보내기 완료`.
- 검증: `test:replay`에서 scrub 값 비움 + 그룹 유지 + 속도/금지 플래그 유지 + 실값 내보내기 값 유지 + scrub 가져오기 성공을 단언. `test:qa` 거부 케이스와 충돌 없음.

## MUST NOT (금지 사항)

- 사이트·포털 전용 셀렉터를 코드에 넣지 않는다. 위험 클릭도 특정 회사 버튼에 묶지 않는다(일반 단어 매칭만).
- `제출` `확인` `저장` `다음` `검색`을 기본 위험 목록에 넣지 않는다.
- `input[type=file]` 값을 채우려 하지 않는다.
- 기존 실값 `EXPORT_DATA` 경로를 바꾸지 않는다(스크럽은 별 동작·별 파일명).
- 전역 `ui:replayPace`를 삭제하지 않는다(프리셋이 없으면 전역을 쓴다).
- 여정(같은 탭)과 그룹(스텝마다 새 탭)을 한 모델로 합치지 않는다.
- 클라우드 동기화·계정 서버·팀 공유·좌석 오픈런·대기열·캡차·보안 키패드를 구현하지 않는다.
- 커밋·푸시를 이 라운드에서 수행하지 않는다(사용자 명시 시에만).
- `dist/`를 직접 편집하지 않는다(`npm run build`만).
