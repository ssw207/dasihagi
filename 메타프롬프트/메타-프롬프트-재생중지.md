# 메타프롬프트 — 재생중지

## 목표 (사용자 요구 원문 포함)
사용자: "재생중지 기능 추가"
→ 현재 단일 프리셋/여정 재생(`APPLY_PRESET`)은 시작 후 중간에 멈출 수 없음. 그룹 실행에만 `RUN_ABORT`가 있고 단일 재생에는 없음. 재생 중 사용자가 중지 버튼을 눌러 즉시 중단할 수 있어야 함.

## 변경 범위 (파일별)
- `background.js` — `replayJourney` 및 `APPLY_PRESET` 흐름에 abort 플래그/토큰 추가, `REPLAY_ABORT` 메시지 핸들러, `journeyReplayTabId`와 분리된 `replayAbortControllers: Map<tabId, {aborted}>` 관리
- `content.js` — `replaySequential` 및 `applyPreset`에 abort 체크, `REPLAY_ABORT` 수신 시 `replayAbort=true` 및 대기 중인 `sleep`/`waitForElement` 해제, `aborted:true` 결과 반환
- `popup/popup.html` — 프리셋 뷰 툴바에 `재생 중지` 버튼(`#btn-stop-replay`, 기본 hidden) 추가
- `popup/popup.js` — 재생 시작 시 버튼 표시/재생 버튼 비활성화, 중지 클릭 시 `REPLAY_ABORT` 전송, 결과 토스트 `재생을 중지했습니다.` 처리, `isReplaying` 상태 관리
- `dist/` — `npm run build`로 재생성
- 테스트 — `test/record-replay-verify.mjs`에 중지 시나리오 1건(3개 필드 중 2번째에서 abort 시 1개만 applied) 추가는 선택, 기존 181 유지가 최소

## 구현 상세
### 메시지 프로토콜
- `REPLAY_ABORT { tabId }` — popup → background → content. background는 `tabId`의 abort 컨트롤러를 `aborted=true`로 마킹하고 `sendToAllFrames(tabId, {type:'REPLAY_ABORT'})` 브로드캐스트. content는 `REPLAY_ABORT`를 받아 `replayAbort` 플래그 세팅.
- 기존 `APPLY_PRESET`/`APPLY_ACTION`은 `waitMs` 동안 abort를 체크해야 함 — `sleep`을 abortable하게 변경.

### background.js
- `const replayAborts = new Map()` — `tabId → {aborted: boolean}`
- `replayJourney(tabId, preset)` 시작 시 `replayAborts.set(tabId, {aborted:false})`, 루프 각 필드 전 `if (ctrl.aborted) break` 또는 `return {applied, failures, aborted:true}`. `navigate` 전후에도 체크. `finally`에서 `replayAborts.delete(tabId)`
- `handleMessage`에 `case 'REPLAY_ABORT'` — `tabId`의 ctrl을 `aborted=true`로, `sendToAllFrames(tabId, {type:'REPLAY_ABORT'})` 후 `{ok:true, aborted:true}` 반환

### content.js
- 전역 `let replayAbort = false; let replayAbortWaiter = null`
- `chrome.runtime.onMessage`에 `REPLAY_ABORT` 분기 — `replayAbort=true`, `replayAbortWaiter`가 있으면 resolve, `sendResponse({ok:true})`
- `sleep(ms)`를 abortable하게: `new Promise(resolve => { if (replayAbort) return resolve(); const t=setTimeout(resolve, ms); replayAbortWaiter=()=>{clearTimeout(t); resolve()}; })` 또는 매 필드 전 체크
- `replaySequential` 시작 시 `replayAbort=false`, 각 필드 루프 첫 줄에 `if (replayAbort) return {applied, failures, aborted:true}`, `waitForElement` 후에도 체크, `applyField`가 blocked여도 abort 우선
- `applyPreset`도 동일하게 abort 시 즉시 `{applied, failures, aborted:true}` 반환

### popup
- HTML: `#presets-view .toolbar` 아래에 `<button id="btn-stop-replay" class="btn btn-danger hidden">재생 중지</button>` 추가 (또는 `run-status-wrap` 옆)
- JS: `let isReplaying=false`, `function setReplaying(on)` — `btn-stop-replay` hidden 토글, 모든 `[data-act="replay"]` 버튼 disabled 토글
- `handlePresetAction('replay')` 시작 시 `setReplaying(true)`, `await sendMessage({type:'APPLY_PRESET',...})` 후 `setReplaying(false)`. 응답에 `aborted`가 있으면 `showToast('재생을 중지했습니다.')`
- `#btn-stop-replay` 클릭 — `sendMessage({type:'REPLAY_ABORT', tabId: currentTabId})`, `setReplaying(false)`는 응답 후 또는 즉시
- 팝업이 닫혀도 background/content의 abort 플래그는 다음 재생 시작 시 리셋되므로 고아 상태 없음

## MUST NOT
- 그룹 실행의 기존 `RUN_ABORT`/`runState` 로직 변경 금지 — 단일 재생 abort는 별도 Map으로 분리
- 재생 실패를 `failures`에 넣지 않고 `aborted`로 구분 — 중지는 실패가 아님
- 저장/암호화/사이트 매칭 로직 변경 금지

## 검증 방법
- `npm run check` — exit 0
- `npm run build` — exit 0
- `npm run test:replay` — 181/181 유지 (신규 abort 테스트는 182로 늘어도 무방)
- 수동: 프리셋(필드 5개, delay 500ms) 재생 시작 → 1초 내 `재생 중지` 클릭 → `재생을 중지했습니다.` 토스트, 남은 필드 미적용, 다음 재생은 정상 동작
- 수동: 여정(페이지 이동 포함) 재생 중 중지 → 이동 중단 및 이후 필드 미실행
