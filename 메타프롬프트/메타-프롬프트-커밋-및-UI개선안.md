# 메타프롬프트 — 커밋 진행 + UI 개선안 제안

## 목표

사용자 요구 원문: **「커밋진행 UI 개선안 제안」**

1. 워킹트리의 미커밋 구현(R11~R14, D28, 문서)을 논리 단위로 커밋한다.
2. 현재 popup/content UI를 보고 **구현하지 않은 채** 개선안을 제안한다.

## 변경 범위

- git 커밋만 (기능 코드 추가 변경 없음, 이 메타프롬프트 파일은 문서 커밋에 포함)
- 산출물: 커밋 + UI 개선안 보고서(응답)

## 구현 상세

### 커밋
- `git status` / `git diff` / `git log`로 범위를 확인한다.
- 논리 분리:
  1. 제품 기능 + 테스트 + dist + README/REQUIREMENTS (R11~R14, D28)
  2. 메타프롬프트·플랜·결정 문서
- `fill-form` 워크트리, `node_modules`는 커밋하지 않는다.
- 커밋 후 `git status`로 확인한다.

### UI 개선안
- popup(목록/편집/그룹/빈 상태), content(녹화 칩/캡처 패널)를 본다.
- 디자이너 × 구현 × PO 교차로 P0/P1/P2를 매긴다.
- 이번 턴에서는 제안만 하고 UI 개편 코드는 넣지 않는다.

## MUST NOT

- 커밋과 무관한 리팩터/기능 추가 금지
- options_page 부활 제안은 P2 이하
- 사이트 하드코딩 금지
- 커밋 메시지에 비밀/PII 금지

## 검증 방법

- `git status --short`가 커밋 대상 기준으로 정리됨
- `git log -5 --oneline`에 새 커밋이 보임
- UI 개선안이 우선순위·수용 기준을 포함함
