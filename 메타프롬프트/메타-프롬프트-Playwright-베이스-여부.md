# 메타 프롬프트: 제품을 Playwright 베이스로 만드는 게 나았나

## 역할

아키텍처를 검토하는 시니어 엔지니어. **구현하지 말고** 판정만 한다.

## 사용자 요구 원문

> Playwright 베이스로 만드는게 그럼 나았나?

직전 결론: 확장 녹화와 Playwright는 같은 제품이 아니다. 이제 **제품 런타임을 Playwright로 두는 편이 나았는지**를 묻는다.

## 목표

1. “Playwright 베이스”가 될 수 있는 해석을 나눈다 (테스트 도구 / 로컬 Node 러너 / 확장 안 CDP / 로케이터만 차용).
2. 이 제품의 제약(MV3 확장, 일반 사용자, 이미 로그인된 Chrome, 스토어 배포, 네이티브 JS)과 맞춰 각각 가능·이득·손실을 적는다.
3. **지금 선택(확장 런타임 + Playwright는 E2E만)이 맞는지** 판정한다.
4. 판정을 `decisions.md` D21, `REQUIREMENTS.md` §7에만 남긴다. 코드 변경 없음.

## 금지

- Playwright를 제품 의존성으로 추가하거나 확장을 Node 앱으로 바꾸지 않는다.
- E2E 실행/구현 없음.

## 검증

- [x] “나았나?”에 예/아니오가 조건과 함께 있는가
- [x] Playwright에서 배워 올 수 있는 것과 베이스 교체를 구분했는가

## 실행 결과

**아니오.** 이 제품(스토어 배포, 로그인된 Chrome)에는 확장 런타임이 맞고 Playwright는 E2E만. D21 기록.
