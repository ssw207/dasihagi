# 메타프롬프트 — 사내 테스트 기안 승인 반영

## 목표

사용자 요구 원문: **「승인」**

직전 산출물인 사내 테스트 한정 기안(`docs/기안-사내테스트-다시하기.md`, 기획팅 K1~K9, §11 승인 요청 1~4)을 **승인된 상태**로 기록한다. 승인 범위는 기안 요청문 그대로다. 범위를 늘리거나 줄이지 않는다.

## 변경 범위 (파일별)

| 파일 | 할 일 |
|------|--------|
| `메타프롬프트/메타-프롬프트-사내테스트-기안-승인.md` | 이 파일 |
| `docs/기안-사내테스트-다시하기.md` | 상태=승인, §11을 승인 결과로 전환 |
| `docs/기획팅-2026-08-30-사내테스트-기안.md` | 기안 승인·다음 단계(파일럿 준비) |
| `기획서.md` | 기안 문서가 승인됨을 한 줄 |
| `REQUIREMENTS.md` | D38, 변경 이력 |
| `.sisyphus/notepads/form-preset-extension/decisions.md` | D38 |
| `README.md` | 기안 링크에 승인 표기 |

코드·스키마·UI·테스트는 건드리지 않는다. 파일럿 실명·기간을 지어내지 않는다.

## 구현 상세

승인된 네 항목 (기안 §11, 변경 없음):

1. 사내 테스트 한정 개발·유지, QA·제휴 운영·스테이징 개발 소수 파일럿
2. 불허: 웹스토어, 고객·협력사 임의 배포, 전사 필수 설치, 운영 사용 권장, 서버형 팀 공유
3. 파일럿 수칙(기안 §6.3)이 사용 조건
4. 기능 추가·범위 확대는 별도 기획팅·기안 없이 하지 않음

다음 단계(문서에만): 파일럿 인원·기간은 사용 부서가 정한다. 이 승인으로 코드를 바꾸지 않는다.

## MUST NOT

- 웹스토어·전사 배포·운영 사용을 승인에 끼워 넣지 않음
- 신규 기능·일정 공수를 승인 부록으로 추가하지 않음
- 허위 결재란(실명 날인) 만들지 않음 — 승인 주체는 사용자 지시 「승인」
- 소스 코드 변경 금지

- K1~K9와 §11 네 항목이 승인 후에도 동일
- `git status`에 문서만
