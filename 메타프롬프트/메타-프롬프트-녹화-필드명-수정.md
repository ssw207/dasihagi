# 메타 프롬프트: 녹화 이후 필드 표시 이름 수정

## 역할

너는 Chrome 확장 프로그램(폼 프리셋, MV3)의 팝업 편집 UX를 고치는 시니어 프론트엔드 엔지니어다. 아래를 **코드 탐색 후** 최소 변경으로 구현하고 검증까지 완료한다.

## 배경 / 사용자 요구 원문

> 녹화후 해당필드의 이름을 수정할수 없다. 녹화이후 필드명을 수정할수 있게 변경

녹화(R9)는 `detectFieldLabel()`로 표시 이름을 자동 생성한다. 편집 화면(`popup.js` `renderFields`)은 값을 입력란으로 고칠 수 있지만, 이름은 `<span class="field-label">`로만 보여 준다. 그래서 자동 이름이 어색해도(예: "필드", placeholder 그대로) 바꿀 수 없다.

## 목표 동작

1. 프리셋 **편집**에서 각 필드의 표시 이름을 직접 수정할 수 있다 (녹화로 만든 필드, 캡처로 만든 필드 모두).
2. **저장**을 누르면 바뀐 이름이 암호화 blob에 반영된다.
3. 목록 카드의 필드 행·재생 결과 라벨도 새 이름을 쓴다.
4. 값 편집, 민감 체크, 삭제, 셀렉터, 타입은 그대로다.

## 핵심 설계

- 데이터 스키마 변경 없음. 기존 `fields[].label`만 편집한다.
- `renderFields`의 이름 `<span>`을 `<input type="text" data-label-edit>`로 바꾼다.
- 값 편집과 같은 패턴: `input` 이벤트에서 `editingPreset.fields[idx].label` 갱신. 저장은 기존 `PRESET_UPDATE`.
- 공백만 남기면 저장 시 `'필드'`로 되돌린다 (녹화 기본값과 동일). XSS는 `escapeHtml` 유지.
- `content.js` 녹화/캡처 패널은 건드리지 않는다. 이름은 **녹화 후 편집**에서 고친다.

## 변경 범위 (파일별)

| 파일 | 변경 |
|------|------|
| `popup/popup.js` | `renderFields` 이름 input, `data-label-edit` 반영, 저장 시 label trim |
| `popup/popup.css` | 이름 input 스타일 (기존 라벨과 비슷한 굵기, 값 input과 구분) |
| `REQUIREMENTS.md` | R13 + D26 + 변경 이력 |
| `.sisyphus/notepads/form-preset-extension/decisions.md` | D26 |
| `README.md` | 녹화 후 편집에서 표시 이름을 바꿀 수 있다고 안내 |

`background.js` / `content.js` / `secure-store.js` 변경 금지.

## 금지 사항 (MUST NOT)

- `fields[]` 스키마 변경, 새 필드 추가.
- 녹화 중 이름 입력 강제 (R9-2 유지: 녹화 자체는 이름 없이).
- 캡처 패널(페이지 위 부동 폼) 동작 변경.
- 값/민감/삭제/셀렉터 편집 제거.
- 빈 이름을 저장해 목록이 깨지게 두기 (trim 후 빈 값이면 `'필드'`).
- `as any` / `@ts-ignore` / 빈 catch.
- `innerHTML`에 사용자 이름을 `escapeHtml` 없이 넣기.
