## 1. 안건

1. 이 확장을 **무엇을 위해** 사내에서 쓸지
2. **사내 테스트 한정**을 어떻게 못 박을지 (배포·환경·데이터)
3. 보안·개인정보 (저장, 내보내기, 운영 계정)
4. 파일럿 대상과 성공 조건
5. 기안에 넣을 승인 요청 항목

코드 변경·신규 기능 우선순위는 이번 안건이 아니다.

## 2. 논의 요약

### 2.1 문제

같은 스테이징·폐쇄망 어드민에 **거의 같은 값**을 매일 넣는다.

- QA: 구매자 A / 판매자 B / 관리자 계정을 엑셀에서 복사하다 한 칸이 틀린다.
- 제휴 운영: 제휴사명만 다르고 정산·수수료·약관 체크 30칸이 같다.
- 개발: localhost 로그인·시드 데이터를 매일 손으로 넣는다.

비밀번호 관리자는 로그인 칸에만 강하고, Playwright/RPA는 이미 로그인한 Chrome·폐쇄망과 설치가 다르다. 필요한 것은 **지금 보고 있는 페이지에서 한 일을 저장하고, 다음에 같은 순서로 다시 하는 일**이다. 제출·결재·결제는 사람이 한다.

이미 v0.1.0 프로토타입이 있다. 이번 회의는 기능을 늘리는 자리가 아니라, **사내 테스트 전용으로 개발·파일럿을 공식화할지**를 정하는 자리다.

### 2.2 용도 한정

보안/IT: 확장이 `<all_urls>` content script를 쓰므로, **전사 필수 설치**나 **웹스토어 공개**는 안 된다. 사용 환경도 스테이징·폐쇄망·로컬로 제한해야 한다.

기획: “테스트 도구”와 “업무 자동화 제품”을 한 문장에 섞지 않는다. 기안 제목부터 **사내 테스트 용도 한정**을 넣는다.

QA: 운영(프로덕션)에서 재생하면 실데이터에 테스트 값이 들어갈 수 있다. **운영 URL에서의 사용을 기안에서 금지**한다. 자동 제출은 그룹에서만 사용자가 고르고, 결제·상신은 녹화되어 있어도 직접 누른다.

### 2.3 데이터

개발: 값은 Chrome 프로필 안 AES-256-GCM. 서버 동기화 없음. 내보내기 JSON에는 실값이 들어간다.

보안/IT: 내보내기 파일을 메신저로 돌리지 않는다. **운영 비밀번호·실고객 PII를 프리셋에 넣지 않는다.** 테스트 계정·더미 값만.

제휴 운영: 제휴사 사업자번호가 테스트용으로 반복되면 프리셋에 둘 수 있다. 실운영 정산 계좌는 넣지 않는다.

### 2.4 배포

개발: `npm run build` → `dist/` → Chrome 개발자 모드에서 압축 해제 로드. 스토어 심사 없음.

보안/IT: IT가 내부 패키지 배포 정책이 있으면 그에 따른다. 없으면 파일럿 인원이 저장소(또는 내부 전달된 `dist`)로 직접 로드. **Chrome 웹스토어, 사외 Git 공개를 전제로 한 배포는 이번 기안 밖.**

### 2.5 파일럿

QA + 제휴 운영 + 스테이징 개발 **소수**. 전 직원 공지·강제 설치 없음.

성공은 “매크로가 항상 된다”가 아니다.

- 테스트 페르소나 전환이 클릭 한 번에 가깝다.
- 고정 체크·셀렉트 누락이 줄어든다.
- 한 건 반복 입력이 수 분에서 수십 초로 줄어든다 (재생 후 이름만 수정).

사이트 개편·동적 검색 결과로 재생이 깨지면 **그 단계만 다시 녹화**한다. 봇 우회는 넣지 않는다.

## 3. 결정 사항

| ID | 결정 | 근거 |
|----|------|------|
| K1 | **사내 테스트 전용**으로만 개발·파일럿한다. 고객 대상 제품, 웹스토어, 전사 필수 설치는 범위 밖이다. | 권한 범위, 오용 방지 |
| K2 | 사용 환경은 **스테이징·폐쇄망 어드민·로컬**이다. 운영(프로덕션)에서의 재생·자동 제출은 금지 안내한다. | 실데이터 오염 |
| K3 | 저장 값은 **테스트 계정·더미**만. 운영 비밀번호·실고객 개인정보를 프리셋에 두지 않는다. 내보내기 JSON은 내부에서만, 메신저 전달 금지. | 보안/IT |
| K4 | 서버·계정 로그인·클라우드 동기화를 만들지 않는다. 값은 사용자 Chrome 프로필 암호화 저장. | 기존 제품 원칙 |
| K5 | 제출·결재·결제는 사람이 한다. 좌석 오픈런·캡차·보안키패드는 하지 않는다. “매크로/봇”으로 부르지 않는다. | 제품 기획서 비목표 |
| K6 | 배포는 **개발자 모드 `dist/` 로드**(또는 IT 내부 패키지). 이번 기안에 스토어 심사를 넣지 않는다. | 개발·보안 |
| K7 | 파일럿은 QA·제휴 운영·스테이징 개발 **소수**. 기존 v0.1.0을 기준으로 공식화한다. 신규 기능은 이 기안에서 약속하지 않는다. | 범위 고정 |
| K8 | 성공 조건은 반복 입력 시간·누락 감소·페르소나 전환이다. 동적 사이트 실패는 한계로 명시하고 재녹화로 대응한다. | QA·기획 |
| K9 | 기안 문서는 `docs/기안-사내테스트-다시하기.md`로 작성하고, 제품 기획서 `기획서.md`는 유지한다. | 문서 역할 분리 |
